# 업무 자동화 기획서 (예시: 해외 출장 경비 환급)

이름: 1회차 수업 예시
작성일: 1회차 실습 기준
자동화 이름 (가제): 해외 출장 개인 경비 환급 처리기

1회차에서 한 해외 출장 개인 경비 환급 실습을 기획서 양식에 거꾸로 채워 본 예시입니다. 회사는 가상의 누리마루산업 주식회사이고, 나는 재무팀 경비 담당자로 사내 메신저 도란에서 신청을 받습니다. 내 기획서를 쓸 때 어느 정도로 쓰면 되는지 감을 잡는 용도입니다.

## 1. 지금 하는 일

AI 생각은 하지 않고, 사람이 손으로 하던 순서입니다.

1. 도란의 채널과 DM 을 열어 직원 20명이 올린 zip 파일을 하나씩 내려받는다.
2. zip 을 풀고 경비환급신청서.xlsx 를 연다. 영수증 사진, 카드 앱 캡처, 스캔본이 같이 들어 있다.
3. 영수증을 눈으로 보고 날짜, 금액, 통화, 가게 이름을 신청서 내용과 맞춰 본다.
4. 여비규정과 해외출장경비처리지침을 펴고, 항목마다 별표 분류표에서 계정과목을 찾고 한도를 확인한다.
5. 외화 금액은 한국은행 ECOS 에서 사용일 환율을 찾아 원화로 바꾼다. 주말과 공휴일이면 직전 영업일 환율을 쓴다. 개인카드는 카드사 청구 원화액을 쓴다.
6. 직원마다 승인, 일부 인정, 보완 요청, 반려를 정하고 사유와 근거 조항을 적는다.
7. 은행별 대량이체 파일 5종, 전표업로드 파일, 정산총괄표, 증빙대장을 만들고 증빙 파일 이름을 규칙에 맞게 바꿔 폴더에 정리한다.
8. 직원마다 결과 회신문을 쓰고, 파일은 재무팀장, 자금 담당, 회계 담당에게 도란으로 보낸다.

## 2. 얼마나 자주, 얼마나 걸리는지

- 주기: 출장이 끝난 뒤 정산 마감일마다
- 한 번 할 때 걸리는 시간: 이틀 정도
- 한 번에 다루는 양: 직원 20명, 영수증 수십 장, 은행 5곳
- 하면서 가장 귀찮은 부분: 영수증을 하나씩 보고 금액을 옮겨 적는 것, 은행마다 이체 파일 양식이 달라 같은 내용을 5번 다시 만드는 것, 직원 20명에게 사유를 따로 써서 회신하는 것

## 3. 입력

| 무엇을 | 어디서 | 어떤 모양으로 |
| --- | --- | --- |
| 직원 신청 묶음 | 도란 채널과 DM | zip (경비환급신청서.xlsx + 영수증 사진, 카드 앱 캡처, 스캔본) |
| 규정 | 사내 문서 | 여비규정(정산규정), 해외출장경비처리지침과 별표 항목별 계정과목 분류표 |
| 환율 | 한국은행 ECOS | API (샘플 키, JPY 와 VND 는 100 단위) |
| 은행별 양식 | 재무팀 | 가상 은행 5곳의 대량이체 템플릿 5종 |

입력 예시를 구할 수 있나요? 예. 직원 20명 분 zip 묶음과 규정 문서, 이체 템플릿 5종.

## 4. 출력

| 누구에게 | 어떤 모양으로 | 언제까지 |
| --- | --- | --- |
| 자금 담당 | 은행별 대량이체 파일 5종 | 지급일 전 |
| 회계 담당 | 전표업로드 파일, 증빙 폴더(이름 변경)와 증빙대장 | 월 마감 전 |
| 재무팀장 | 정산총괄표 (직원별 결과와 사유) | 처리 직후 |
| 직원 각자 | 회신문 (승인, 일부 인정, 보완 요청, 반려와 사유 코드, 근거 조항) | 처리 직후 |
| 재무팀 보관용 | 회신기록 | 처리 직후 |

## 5. 모듈 그림

```
[입력]
  무엇: 직원 20명의 신청 zip
  어디서: 도란 채널과 DM
      ↓
[모듈 1: 도란에서 받기]              추출
  하는 일: 채널과 DM 의 zip 을 내려받는다
  입력: 도란 메시지
  출력: inbox/ (직원별 zip)
      ↓
[모듈 2: 압축 풀기·신청서 읽기]      추출
  하는 일: zip 을 풀고 신청서.xlsx 의 표를 읽는다
         영수증 사진 속 날짜, 금액, 통화는 영수증 읽기 모듈에 맡긴다
  입력: inbox/
  출력: 직원별 신청 내용 + 영수증 읽기 결과
      ↓
[모듈 3: 환율 받기]                  추출
  하는 일: 사용일 기준 한국은행 ECOS 매매기준율을 받는다
         주말과 공휴일은 직전 영업일, JPY 와 VND 는 100 단위
  입력: 사용일, 통화
  출력: 환율표
      ↓
[모듈 4: 규칙 판정]                  변환
  하는 일: 환산, 한도 비교, 중복과 누락 점검, 결과 4종 결정
         항목 유형 분류는 유형 분류 모듈에 맡긴다
  입력: 신청 내용 + 환율표 + 규정
  출력: result.json
      ↓
  result.json 하나에서 갈라져 나간다
      ↓
[모듈 5: 결과 파일 만들기]           적재
  하는 일: 은행별 대량이체 파일 5종, 전표업로드, 정산총괄표,
         증빙 폴더(이름 변경)와 증빙대장을 만든다
  입력: result.json + 은행별 템플릿
  출력: out/ 폴더
      ↓
[모듈 6: 회신 모듈]                  변환
  하는 일: 직원마다 결과와 사유 코드, 근거 조항으로 회신문을 쓴다
  입력: result.json
  출력: 회신문, 회신기록
      ↓
[모듈 7: 도란으로 보내기]            적재
  하는 일: 파일은 재무팀장, 자금 담당, 회계 담당에게, 회신문은 직원 각자에게 올린다
  입력: out/ + 회신문
  출력: 도란 메시지
      ↓
[출력]
  누구에게: 재무팀장, 자금 담당, 회계 담당, 직원 20명
  어떤 모양으로: 이체 파일, 전표, 총괄표, 증빙 폴더, 회신문
```

판단 자리 표시는 다음과 같습니다.

- 모듈 2 안의 영수증 읽기 모듈: AI (claude -p, sonnet)
- 모듈 4 안의 유형 분류 모듈: AI (claude -p, haiku, 처리지침 근거)
- 모듈 6 의 회신 모듈: AI (claude -p, haiku)

나머지는 전부 AI 없이 도는 일반 코드입니다. 가운데 result.json 이 모든 출구가 함께 쓰는 중간 데이터이므로, 출구를 하나 더 늘려도 모듈 1부터 4까지는 건드리지 않습니다.

## 6. 판단이 필요한 자리

| 모듈 | 어떤 판단인가 | 규칙으로 쓸 수 있나 | AI 슬롯 후보 |
| --- | --- | --- | --- |
| 영수증 읽기 모듈 | 사진, 캡처, 스캔 속 날짜와 금액, 통화, 가게 이름 읽기 | 아니오 | 예 (sonnet) |
| 유형 분류 모듈 | 영수증 내용이 처리지침 별표의 어느 항목, 계정과목인지 정하기 | 아니오 | 예 (haiku) |
| 회신 모듈 | 결과, 사유 코드, 조항을 직원에게 보낼 문장으로 풀어 쓰기 | 아니오 | 예 (haiku) |

AI 슬롯 개수: 3개

한도 초과, 중복 청구, 증빙 누락 판정과 환율 고르기, 파일 채우기는 조건으로 쓸 수 있어서 표에 넣지 않았습니다.

이유는 모듈마다 다릅니다.

- 영수증 읽기 모듈: 영수증은 사진이고 가게마다 모양이 다릅니다. 글자 위치와 표기가 일정하지 않아 "몇 번째 줄이 금액이면" 같은 조건으로 쓸 수 없습니다. 읽은 값은 JSON 으로만 받습니다.
- 유형 분류 모듈: "식당 영수증이 식비인지 접대비인지"는 가게 이름과 품목의 뜻을 읽어야 정해집니다. 처리지침 별표 내용을 근거로 붙여 분류하게 하고, 분류 뒤의 한도 비교는 규칙이 합니다.
- 회신 모듈: 결과 4종과 사유 코드는 규칙이 이미 정했습니다. 남은 일은 직원마다 다른 상황을 조항과 함께 정중한 문장으로 풀어 쓰는 것이어서, 문장 템플릿 하나로는 20명의 사정을 담을 수 없습니다.

세 모듈 모두 출력 모양을 JSON 으로 정해 두고, 그 뒤 계산과 판정은 일반 코드가 이어받습니다. 금액 계산과 지급 결과에는 AI 가 끼지 않습니다. 같은 입력에는 같은 이체 금액이 나와야 하기 때문입니다.

## 8. PoC 순서

| 순서 | 모듈 | 이유 | 입력 예시 파일 | 기대 출력 파일 |
| --- | --- | --- | --- | --- |
| 1 | 규칙 판정 | 외부 호출이 없고 규칙만 있어 결과를 눈으로 맞춰 보기 쉽다 | 신청 내용 샘플, 환율표 샘플 | result.json |
| 2 | 결과 파일 만들기 | 같은 result.json 에서 파일을 내보낼 뿐이라 양식과 대조하기 쉽다 | result.json, 이체 템플릿 | out/ 폴더 |
| 3 | 환율 받기 | 키와 네트워크가 필요해서 앞 단계가 굳은 뒤에 | 사용일, 통화 목록 | 환율표 |
| 4 | 압축 풀기·신청서 읽기 | 영수증 읽기 모듈을 붙이기 전에 표 읽기만 먼저 확인 | 직원 zip 샘플 | 신청 내용 |
| 5 | 영수증 읽기, 유형 분류, 회신 | AI 모듈은 입출력 모양이 굳은 뒤에 하나씩 | 영수증 샘플, result.json | JSON, 회신문 |
| 6 | 도란에서 받기, 도란으로 보내기 | 마지막에 앞뒤를 묶는다 | 도란 채널 | 전체 실행 결과 |

첫 번째로 만들 모듈 한 줄 요약: 규칙 판정은 신청 내용과 환율표를 읽어서 직원마다 승인, 일부 인정, 보완 요청, 반려와 사유 코드를 붙인 result.json 을 만든다.
