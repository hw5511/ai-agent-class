# 모듈 PoC 가이드

PoC 는 "되는지 한번 만들어 보는 것"입니다. 기획서의 모듈 그림에서 모듈 하나만 골라 Claude Code 로 만들고, 확인이 끝나면 다음 모듈로 갑니다. 전체를 한 번에 만들어 달라고 하지 마세요.

## 순서

1. 기획서 8번에서 첫 모듈을 고릅니다. 입력이 단순하고 결과가 눈에 보이는 것이 좋습니다.
2. 그 모듈의 입력 예시를 파일로 만듭니다. 진짜 데이터 3줄에서 10줄이면 충분합니다.
3. 기대하는 출력도 손으로 한 번 써 둡니다. 정답지입니다.
4. Claude Code 에게 입력 예시와 기대 출력을 주고, 그것만 하는 가장 작은 스크립트를 부탁합니다.
5. 예시로 실행하고, 결과를 내 눈으로 정답지와 맞춰 봅니다. Claude 가 맞다고 해도 내가 확인합니다.
6. 입력 예시와 출력 예시를 스크립트 옆에 저장합니다. 나중에 고칠 때 다시 돌려 볼 기준이 됩니다.
7. 다음 모듈로 넘어갑니다. 앞 모듈의 출력 예시가 다음 모듈의 입력 예시가 됩니다.

## 프롬프트 예시

처음 만들 때:

```
@입력예시.csv 를 읽어서 상태가 폐업이거나 미등록인 줄만 골라 result.json 으로 저장하는 스크립트를 만들어줘. 다른 모듈은 아직 만들지 마
```

기대 출력을 같이 줄 때:

```
@입력예시.json 을 넣으면 @기대출력.json 과 똑같이 나오는 process.py 만 만들어줘. 규칙은 폐업은 위험, 휴업은 주의야. 실행해서 결과 비교까지 해줘
```

결과가 틀렸을 때:

```
출력예시와 3번째 줄이 달라. 어디서 갈라졌는지 먼저 말해주고, 그 부분만 고쳐줘. 다른 곳은 건드리지 마
```

다음 모듈로 넘어갈 때:

```
방금 만든 process 의 출력인 @result.json 을 입력으로 받아서 report.md 만 쓰는 스크립트를 만들어줘. process.py 는 수정하지 마
```

## 지킬 것

- 한 번에 모듈 하나. 프롬프트마다 "다른 모듈은 아직 만들지 마"를 붙입니다.
- 실행해 보기 전에는 끝난 게 아닙니다.
- 판단이 필요한 자리도 먼저 규칙으로 써 봅니다. 규칙이 안 될 때만 AI 슬롯입니다.
